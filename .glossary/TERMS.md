# lexema domain vocabulary (TERMS)

The repo-owned vocabulary spine. One row per term: the canonical definition, and where a name has
drifted, what the term is **not**. When the code and this file disagree, the code is authoritative
and this file is the doc to fix.

## Source data
| Term | Definition | Not |
|---|---|---|
| embedded form | One entry of a record's `forms[]`, indexed as `embedded-form` evidence with its own tags and a `/forms/<i>` pointer (`src/core/candidateResolver.ts`). The same surface can also exist as a separate record; a lookup keeps both as evidence. | a separate record |
| form-of record | A source record tagged `form-of` whose sense carries `form_of[].word` naming the lemma it inflects. The target resolves only when exactly one record matches; otherwise the relation is counted as unresolved or ambiguous (`resolveCandidates` in `src/core/candidateResolver.ts`). | a resolved lemma — the pointer is evidence, not the answer |
| headword | A source record's `word`. Every Italian record is indexed under it as `headword` evidence, whether the record is a lemma or itself a form-of record (`SourceEvidence.kind` in `src/core/types.ts`; `src/core/candidateResolver.ts`). | a lemma — a headword can be an inflected form with its own record |
| release | One immutable import of a source file, identified by `releaseId` and carrying source, licence, retrieval time and compressed SHA-256 (`ReleaseMetadata` in `src/core/types.ts`). A provenance ref's `release_id` names it. | a Git release or tag |
| raw page | One revision of one Italian Wiktionary page, saved verbatim with its revision id (`RawPage` in `src/source/rawPage.ts`). The second upstream input beside the archive; the recovered layer reads it through a `RawPageSource`. | the archive record extracted from it |
| recovered definition | A definition a raw page states below `#` that its archive record does not carry as a definition — absent from the record, or, rarely, filed under an example — read by page structure and stored beside the record with the page revision and line it came from (`recovered_definition` in `src/db/schema.sql`; `src/italian/recovery.ts`). The page marks it *recovered*. | a gloss — the record is never edited — or a Lexema-written definition |
| page control | A `#` line with no prose of its own: headword template, gender/number stamp, plural link. The extraction makes it a sense whose gloss is furniture (`casa ( approfondimento) f sing`); the lines below it are the definitions (`src/italian/wikitext.ts`). | a definition |
| list note | A parenthetical note inside a `synonyms`, `antonyms` or `derived` list that the extraction split on its commas, so it lands as entries whose brackets do not balance: `casa`'s `(per es. rurale`, `civile`, `industriale)`. Found by structure alone, rejoined in source order, and shown as text where it sat, never as a search (`relatedItems` in `web/lib/dictionary/relatedList.ts`). The record keeps the pieces as imported. | a word — a piece is not a search |
| missing-field placeholder | The fixed sentence Wikizionario prints where a page has no hyphenation, definition, etymology or references — `→ Etimologia mancante. Se vuoi, aggiungila tu.`, `definizione mancante; se vuoi, aggiungila tu` — which the archive keeps as the field's text. A lookup reads it as no data, keeping any real text beside it (`withoutPlaceholder` in `src/italian/placeholder.ts`, #255); the stored rows keep it as imported. | real text that says "mancante", such as "giorni mancanti"; a source text normalization, which rewrites stored rows |
| source text normalization | A fixed, rule-based rewrite of source-derived text in the structured rows, so one meaning reads one way across the dictionary: the first rewrites a form gloss's "1ª persona" as "prima persona" (#257). It never changes meaning, runs at import and as a one-off update, and leaves `source_record_json` byte-for-byte ([ADR 0019](../.decisions/0019-source-text-may-be-normalized.md)). | Italian normalization for search matching (`src/italian/normalize.ts`), or a correction of what the source says |
| source example | A `senses[].examples[].text` string returned on a candidate only when it contains the exact searched surface after Italian normalization (`containsExactItalianSurface` in `src/italian/normalize.ts`); any other example is counted as rejected. | a generated sentence |

## Lookup
| Term | Definition | Not |
|---|---|---|
| candidate | One result of a lookup: a target record plus every piece of evidence that led to it, with its definitions, forms, articles, examples and provenance (`Candidate` in `src/core/types.ts`). A lookup returns every candidate the source supports; `sale` yields the salt noun, the plural of `sala` and the form of `salire`. | the chosen answer — ranking is a later, advisory step |
| provenance ref | The pointer every derived value carries, named as the schema names it: `release_id` the release, `line_no` the 1-based physical line of the source record, `json_pointer` inside that record, and `line_sha256` the digest of that line (`src/db/schema.sql`; `docs/RECORD_IDENTITY.md`). Code that carries a ref uses these four names. | the compact `{ r, i, p, h }` in `src/core/types.ts`, which is the pre-schema validation spike, not the contract |
| unclassified form | A surface form kept with its raw tags and a `reason` when its grammar cannot be mapped safely (`UnclassifiedForm`; `targetForms` in `src/italian/adapter.ts`). It is returned, not dropped, and no article is generated from it. | an error |

## API
| Term | Definition | Not |
|---|---|---|
| API key | The secret a client of the JSON API sends as `X-API-Key`. Stored only as its SHA-256, with its own label (`api_key` in `src/db/app/schema.ts`; `src/api/keys.ts`). Either an admin key or an owned key. | a visitor key — the per-visitor rate-limit identity the site derives from an address (`visitorKey` in `web/worker/rateLimit.ts`) |
| admin key | An API key made with `pnpm run api-key` (`src/api/keyCli.ts`). It has no owner (`owner_account_id` is NULL), carries its own per-minute limit, and no developer account can list or revoke it. | an owned key |
| owned key | An API key a developer account made for itself (`src/api/ownedKeys.ts`). It carries no per-minute limit of its own: its rate is its account's, and the schema refuses one that has a limit. It may be limited to some endpoints and given an expiry (`src/api/keyAccess.ts`); an admin key has neither. Its owner is that account; only that account lists or revokes it, and a deleted account's owned keys stay stored, revoked. | an admin key |
| display prefix | A key's first 11 characters, `lx_` and 8 hex digits, stored beside its hash so the key can be named without its secret (`displayPrefix` in `src/api/keys.ts`). | the key — the rest is never stored |
| call | What API usage is counted in: every answered request is 1 call, and `lookup/batch` is 1 call per word it is sent (`CALL_BASIS` and `callCost` in `src/api/calls.ts`; Huey, #183). Summed per key per UTC day in `api_key_usage.calls`. | a request — a batch of 7 words is one request and 7 calls; nor the retired *unit*, the per-endpoint weight calls replaced (#201) |

## Developer site
| Term | Definition | Not |
|---|---|---|
| developer account | A person signed in to developers.lexema.fyi: better-auth's user, one row of `developer_account` (`src/accounts/accounts.ts`, `src/accounts/auth.ts`). It keeps the verified email it was made with, which a second provider links by, and its first provider's name; the account menu names it from its provider identities. Created on the first sign-in under a verified email no account has. Deleting it (`deleteAccount`, Lexema's, not better-auth's) revokes its keys, removes its sessions and identities, and replaces its email and name with values that say nothing about the person; the row stays, marked deleted, so its keys and usage keep an owner, and the next sign-in under that email makes a new account. | a Google or GitHub account — that is a provider identity |
| provider identity | One Google or GitHub account linked to one developer account: better-auth's account, by the provider's own id for the person, with the verified email it was linked with (`provider_identity` in `src/db/app/schema.ts`). It also keeps the name the provider gives the person, refreshed at each sign-in, for the account menu, and none of the provider's tokens. A second provider's identity with the same verified email links to the same account. | the account itself, or an unverified email, which is never stored |
| session | A signed-in browser: better-auth's session, a random token stored with its account and expiry (`developer_session`), carried in a host-only `__Secure-` cookie on developers.lexema.fyi with better-auth's signature of it, made with `BETTER_AUTH_SECRET` (`src/accounts/auth.ts`). The token alone signs nobody in. It lasts 30 days and ends at sign-out or when its account is deleted. | an API key — a session never authenticates an API call |

## Hosting
| Term | Definition | Not |
|---|---|---|
| app database | The D1 bound as `APP_DB`, holding what the site itself writes: developer accounts, API keys, plans, usage and reader reports, in the Drizzle-defined app tables ([ADR 0017](../.decisions/0017-better-auth-and-drizzle-own-accounts.md)). One per stage: a local one, one per Preview (`lexema-preview-app-<name>`, where `<name>` is the Preview's name, made and migrated by the preview command), and production's ([ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | the dictionary database (`DB`), which holds the release, is shared by production and every Preview, and is never written by code |
| Preview | A Cloudflare Worker Preview of `lexema-web` for one branch, built by Workers Builds on each push. Its name is its branch's name made into a DNS label (`web/builds/previewName.ts`, [docs/DEPLOY.md](../docs/DEPLOY.md#the-preview-name)). It answers the three sites at `<name>.preview.lexema.fyi`, `<name>.developers-preview.lexema.fyi` and `<name>.api-preview.lexema.fyi`, runs on the `preview` stage, reads the shared dictionary database and writes only to its own app database. The sweep on each merge to `main` deletes it once its branch has no open pull request ([ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | a version preview URL (`wrangler versions upload --preview-alias`), which shares production's bindings; nor production |
| stage | Where the Worker is running, read from the `LEXEMA_STAGE` var: `local`, `preview` or `production`, parsed into a closed type so any other value refuses to boot. Preview-only behaviour, such as `X-Robots-Tag: noindex`, keys on it ([ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | a Wrangler environment (`env.production`), which is a build-time config block; nor a release's `importing`/`complete` status |
