# lexema domain vocabulary (TERMS)

The repo-owned vocabulary spine. One row per term: the canonical definition, and where a name has
drifted, what the term is **not**. When the code and this file disagree, the code is authoritative
and this file is the doc to fix.

## Source data
| Term | Definition | Not |
|---|---|---|
| embedded form | One entry of a record's `forms[]`, indexed as `embedded-form` evidence with its own tags and a `/forms/<i>` pointer (`src/core/candidateResolver.ts`). The same surface can also exist as a separate record; a lookup keeps both as evidence. | a separate record |
| declared lemma | A word no served record heads, lists or spells as a phrase, that `form_of` edges of served records name: `verbalizzare` has no record, and its form records say "prima persona singolare dell'indicativo presente di verbalizzare". The page's search shows it with the forms those records declare, each placed by the gloss of its edge (`it-verb-form-gloss/v1`, `it-plural-gloss/v1`), one reading per part of speech and no definition (`declaredLemma` in `src/lookup/declaredLemma.ts`; `DeclaredLemmaResult` in `src/lookup/types.ts`; #453). The developer API's lookup does not reach it. | a reading — it has no record, so no `recordId` and no definition; a dangling link — that is the form's side of the same edge |
| form-of record | A source record tagged `form-of` whose sense carries `form_of[].word` naming the lemma it inflects. The target resolves only when exactly one record matches; otherwise the relation is counted as unresolved or ambiguous (`resolveCandidates` in `src/core/candidateResolver.ts`). | a resolved lemma — the pointer is evidence, not the answer |
| headword | A source record's `word`. Every Italian record is indexed under it as `headword` evidence, whether the record is a lemma or itself a form-of record (`SourceEvidence.kind` in `src/core/types.ts`; `src/core/candidateResolver.ts`). | a lemma — a headword can be an inflected form with its own record |
| release | One immutable import of a source file, identified by `releaseId` and carrying source, licence, retrieval time and compressed SHA-256 (`ReleaseMetadata` in `src/core/types.ts`). A provenance ref's `release_id` names it. | a Git release or tag |
| master | The dictionary database as it is served: the complete release it was seeded from, which `LEXEMA_RELEASE` names, plus the changes chosen from later releases. Its releases are the view `served_release`, and its records the view `served_record` (`src/db/schema.sql`; [docs/UPDATES.md](../docs/UPDATES.md)). | a release — a master can hold records of several |
| feed release | A later kaikki release changes were applied to the master from: a `feed_release` row, its `source_release` status `partial`, since only the chosen records landed (`src/update/apply.ts`). | a replacement — it is never served whole, and never re-imported |
| change | One difference a later release would make to the master, as the diff finds it by matching records by content, the fields Lexema reads (`READ_FIELDS` in `src/update/content.ts`), within a `(word, pos)` group: a new word, a changed record (filed as *changed or fixed senses* when its senses differ), or a lost word. Its id is `new-`, `chg-` or `lost-` and twelve hex digits, the same on every run (`src/update/changes.ts`). A lost word is reported, never applied. | an ambiguous group, which the diff names and offers no change for; a record id or a line number, neither of which is stable between files |
| selection | The verdicts of a fixed rule over a diff: `feed-selection/v6` takes eligible new Italian words, safely matched newer definition corrections, rewrites and removals, and changed translations under the same senses under ADR 0025, including another update to an earlier-applied record, and skips a removal that leaves an empty, placeholder or page-hidden sense in its place (`src/update/selection.ts`). `update:auto` composes selection and apply without per-word choice. | a semantic accuracy review or a whole-release replacement |
| retired record | A master record a changed record replaced: its `lookup_form` and `form_of_edge` rows are removed, so no search reaches it, and every other row stays. The rows written by hand beside it stay attached to it and are read for the record that replaced it (`applied_change`; `lineageOf` in `src/lookup/served.ts`), except its curated corrections: its `corrected_claim`, `corrected_form` and `corrected_edge` rows stay beside it with their evidence, no lookup reads them, and the update reports them. A `hidden_recovered_definition` row stays the same way: the recovered definition it hides is still read for the record that replaced it, and is shown there. | a deleted record |
| hidden record | A record the archive tags Italian that a hiding rule finds is another language's: `section-language/v1` (`src/italian/sectionLanguage.ts`) reads it off the raw page, `form-of-foreign-lemma/v1` (`src/italian/formOfForeignLemma.ts`) off a foreign record that lists it among its forms. It is seeded whole, its line in `source_record_json` byte for byte, but has no `lookup_form` or `form_of_edge` rows, so nothing a reader asks reaches it, and no lookup reads a `corrected_edge` row on it; its `hidden_record` row names the rule and its evidence, the page line or the foreign record's archive line ([ADR 0023](../.decisions/0023-foreign-records-are-hidden-not-deleted.md)). | a deleted record; a retired record, which a later record replaced |
| curated correction | A record's own gender or number that the source states wrongly, set right on Huey's ruling: `fissazione` is tagged masculine and is feminine, and `ammaliatrice` glosses itself "plurale di ammaliatore" and is its feminine singular (#420). An entry is written by hand, or made by a ruled rule from pinned Wiktionary revisions, each citing the revision that confirms it (`it-plural-gloss-number/v3` in `src/italian/pluralGlossNumber.ts`, #483, #515, #516, [ADR 0027](../.decisions/0027-curated-corrections-are-cited-exceptions.md)'s amendment). Each entry of the committed list (`CURATED_CORRECTIONS` in `src/italian/curatedCorrections.ts`) names its record by release, archive line and line digest, the source text it overrides, and a cited Wiktionary revision. It is stored beside the record as `corrected_claim` rows, and a lookup reads it in place of the record's claims in that dimension, keeping them (`CorrectedClaim` in `src/lookup/types.ts`). A record that replaced the corrected one does not inherit it; the update reports it instead. The list also sets a sense's `form_of` edge where the source states none or names the wrong word (ADR 0030, #722): `aerei`'s "plurale di aereo" gets an edge to `aereo`, citing two it.wiktionary pages at the revisions the archive was extracted from, `aerei`'s, which shows that gloss, and `aereo`'s, whose forms table lists `aerei` (Huey's [ruling](https://github.com/povlabs/lexema/issues/722#issuecomment-6058471600) of 2026-10-08); rule `it-form-of-gloss-edge/v2` (`src/italian/formOfGlossEdge.ts`, #733) makes most such entries, and keeps a replaced edge verbatim beside its correction (`porta`'s `presente`, replaced by `portare`). It may also remove the edge of a meaning sense, whose gloss names no form, keeping the removed edge verbatim and citing the record's own page, or point it at the record's own base word where a real form sense names one: `mele`'s "percosse" no longer names `percosse` but `mela`, and `scandinava`'s "relativa alla Scandinavia" names nothing (rule `it-form-of-meaning-edge/v1` in `src/italian/formOfMeaningEdge.ts`, #755, ADR 0030's 2026-10-09 amendment). It is stored as a `corrected_edge` row, which a lookup reads in place of the sense's own edges; a removal's row names no word. The list also holds definition corrections (#450): a page-only entry's definition that the page itself states wrongly (`grufolare` gives *grugnire*'s sense), named by page title, dump revision, the definition's place and its verbatim line and text, and replaced by Lexema's wording that Huey approved. It is stored as a `corrected_definition` row, and a lookup reads its wording in place of the page's (`RecoveredDefinition.correction`). An entry read from another revision, or none, does not get it; the seed and `correct:records` report it instead. The list also holds table-cell corrections ([ADR 0030](../.decisions/0030-corrections-may-fix-edges-and-cells.md), #723): cells of a verb's conjugation table the source spells wrongly (`assorbire`'s `siamo assorbito, assorti, assorti`), named like a record's gender or number and each cell by its place in `forms[]` and the text the line holds there. They are stored as `corrected_form` rows, and a lookup reads each cell's spelling in place of the source's, keeping it (`SourceForm.corrected`). The list also hides a recovered definition whose line states no dictionary word ([ADR 0030](../.decisions/0030-corrections-may-fix-edges-and-cells.md)'s second 2026-10-09 amendment, #773): `diplomatizzare`'s `{{Transitivo|it}}hhhhhhhh`, named by its record, its page line and that line's wikitext and text, citing the page revision and Huey's ruling. It is stored as a `hidden_recovered_definition` row, and a lookup reads the record as having no such definition, keeping the `recovered_definition` row. The page shows the corrected fact and no mark of the correction. | a source text normalization, which never changes meaning; an edit of the record or entry, whose line, `grammar_claim`, `lookup_form`, `form_of_edge` and `entry_definition` rows stay as imported; a generated explanation, which is labelled (ADR 0008) |
| hand-kept reading | A whole reading the source lacks, kept by hand beside the source data on Huey's ruling ([ADR 0031](../.decisions/0031-hand-kept-readings-fill-source-gaps.md), #745): a word, a part of speech from the closed set and its Italian definitions, each paraphrasing a sense line of the en.wiktionary revision it cites. `si` has no pronoun record and `come` no conjunction, because Italian Wiktionary has no such section. Each entry of the committed list (`HAND_KEPT_READINGS` in `src/italian/handKeptReadings.ts`) cites its revision by permanent link and names its ruling, and its wording is Huey's approved text. It is stored as `hand_kept_definition` rows, one per definition, and a lookup reads it beside the source's readings of its word, with no mark (`src/lookup/handKept.ts`). | a curated correction, which sets one fact of a record or entry that exists; a recovered entry, which a rule reads off a raw page (ADR 0024); generated text, which is labelled (ADR 0008) |
| change declaration | A JSON file under `dictionary-changes/` that states one write to the shared dictionary: the command (`update:upgrade`, `update:auto`, `hide:records`, `normalize:source-text`, `correct:records` or `load:page-entries`), its inputs, the counts its plan is expected to have, and optionally `lookups`, up to 10 of its own words the dictionary deploy looks up after the write (#554). One file per change; `parseDeclaration` refuses a malformed file or an unknown command, naming the file (`src/update/declaration.ts`, #455). The pull request that adds one may leave the counts out until the pull request plan check gives them. | a change, which the diff finds in a later release; the SQL the command writes |
| plan-only run | A run of one of the six dictionary write commands with `--plan-only`: it builds the same SQL file and counts (`PlanCounts` in `src/update/planCounts.ts`) the command would apply, and runs nothing on the database (`src/update/planOnly.ts`, #455). Its counts are held against a change declaration and the hard limits: more than 100 records removed, or more than 5% of the records changed or removed. | a diff or a selection, which report a later release and plan no write |
| dictionary deploy | The run of `.github/workflows/dictionary-deploy.yml` on a push to `main`: it applies the change declarations added in `production..main` to the shared dictionary behind a Time Travel bookmark, a plan check, a read-back and a word lookup, then fast-forwards `production`, which Workers Builds deploys the site from. When that range adds or changes nothing under `dictionary-changes/`, its `gate` job only fast-forwards `production`, with no secret (#521). A red run leaves `production` unmoved and never restores by itself (`src/deploy/dictionaryDeploy.ts`, [docs/DEPLOY.md](../docs/DEPLOY.md#the-dictionary-deploy), #456). | the site deploy, which Workers Builds runs from `production`; the one-time seed upload |
| pull request plan check | The run of `.github/workflows/dictionary-plan.yml` on a pull request that adds a change declaration: it plans the first declaration added with the pull request's own code against the shared dictionary, through a D1 read-only token, and holds it to `expected`, printing the counts when they differ or are missing. `update:auto`, `hide:records` and `load:page-entries` read their archive and dump from the public `povlabs/lexema-data` with no token. It writes nothing and refuses to count a later declaration in the same pull request. A later push that changes nothing under `dictionary-changes/` skips the plan when the plan on the previous head concluded success (`src/deploy/pullRequestPlan.ts`, [docs/DEPLOY.md](../docs/DEPLOY.md#the-pull-request-plan-check), #494, #498, #521). | the dictionary deploy, which writes at merge and holds every declaration to `expected` again; the plan-only entry run by hand or by the monthly release |
| raw page | One revision of one Italian Wiktionary page, saved verbatim with its revision id (`RawPage` in `src/source/rawPage.ts`). The second upstream input beside the archive; the recovered layer reads it through a `RawPageSource`. | the archive record extracted from it |
| recovered definition | A definition a raw page states below `#` that its archive record does not carry as a definition — absent from the record, or, rarely, filed under an example — read by page structure and stored beside the record with the page revision and line it came from (`recovered_definition` in `src/db/schema.sql`; `src/italian/recovery.ts`). The page marks it *recovered*. | a gloss — the record is never edited — or a Lexema-written definition |
| verb-type part | The lines of a Verbo section from a line that starts with `{{Transitivo\|it}}`, `{{Intransitivo\|it}}`, `{{Riflessivo\|it}}` or `{{Reciproco\|it}}` to the next such line or the section's end (`VerbPart` in `src/italian/wikitext.ts`; `src/italian/verbType.ts`). The extraction makes one record of each part, tagged with its type (`urgere`: archive lines 43705 `intransitive` and 43706 `transitive`), and a definition recovered from a part belongs to the records whose tags name it ([ADR 0029](../.decisions/0029-recovered-layer-reads-bullet-prose-lines.md), #775). | a section — the parts share one heading and one part-of-speech title; a usage label, which the template also prints on its line |
| page control | A `#` line with no prose of its own: headword template, gender/number stamp, plural link. The extraction makes it a sense whose gloss is furniture (`casa ( approfondimento) f sing`); the lines below it are the definitions (`src/italian/wikitext.ts`). | a definition |
| gloss grammar stamp | The gender letter and optional number word (`f sing`, `m`) a page control leaves at the end of a gloss, when the whole gloss is that line: `casa ( approfondimento) f sing`, `presina f`, `m sing`. Rule `it-gloss-stamp/v1` lifts it into stated gender and number claims pointing at the gloss, and stores the gloss without it, for a noun or adjective with no gender tag (`GlossStampLift` in `src/import/grammarPolicy.ts`, #317). | a trailing `m` after prose, such as the metre in `altezza di 1 m`; a record `tag` |
| list note | A parenthetical note inside a `synonyms`, `antonyms` or `derived` list that the extraction split on its commas, so it lands as entries whose brackets do not balance: `casa`'s `(per es. rurale`, `civile`, `industriale)`. Found by structure alone, rejoined in source order, and shown as text where it sat, never as a search (`relatedItems` in `web/lib/dictionary/relatedList.ts`). The record keeps the pieces as imported. | a word — a piece is not a search |
| headword echo | A gloss that is its record's headword and nothing more, compared ignoring case, accents, apostrophes and the punctuation around it: `presina` once its stamp is lifted from `presina f`, `sci di fondo;`. A lookup reads it as no gloss, like the missing-field placeholder; the stored rows keep it as imported (`isHeadwordEcho` in `src/italian/headwordEcho.ts`, #395). | a gloss that contains the headword inside a meaning (`sport associato all'attività di andare sugli sci`); page furniture (`casa ( approfondimento)`) |
| missing-field placeholder | The fixed sentence Wikizionario prints where a page has no hyphenation, definition, etymology or references — `→ Etimologia mancante. Se vuoi, aggiungila tu.`, `definizione mancante; se vuoi, aggiungila tu` — which the archive keeps as the field's text. A lookup reads it as no data, keeping any real text beside it (`withoutPlaceholder` in `src/italian/placeholder.ts`, #255); the stored rows keep it as imported. | real text that says "mancante", such as "giorni mancanti"; a source text normalization, which rewrites stored rows |
| source text normalization | A fixed, rule-based rewrite of source-derived text in the structured rows, so one meaning reads one way across the dictionary: the first rewrites a form gloss's "1ª persona" as "prima persona" (#257), another drops the empty plural template "inserisci qui voce al plurale" from `forms[]` (#342), and another stores a gloss the headword line leads (`palo ( approfondimento) pezza onorevole…`) as the definition after the link (#325). Each rule has a name and version, such as `form-plural-placeholder/v1` (`SOURCE_TEXT_RULES` in `src/italian/sourceTextNormalization.ts`). It never changes meaning, runs at import and as a one-off update, and leaves `source_record_json` byte-for-byte ([ADR 0019](../.decisions/0019-source-text-may-be-normalized.md)). | Italian normalization for search matching (`src/italian/normalize.ts`), or a correction of what the source says |
| translation | One `translations[]` entry of a record, as the source wrote it: a language code (`lang_code`, `en`), the language's Italian name (`inglese`), the word in that language, and an optional `sense` label for the meaning it translates (`automobile`). The source copies a page's whole table onto every record of that page, so a record's list is its page's, not one meaning's. A lookup reads it off the record's own line (`readTranslations` in `src/lookup/sourceRecord.ts`; `Translation` in `src/lookup/types.ts`), and the API serves it as the `translations` section, kept to `lang` (#739). | a Lexema translation, which none is; a sense's own list, since the label is text and never a sense index; a lemma's list carried onto its forms |
| source example | A `senses[].examples[].text` string returned on a candidate only when it contains the exact searched surface after Italian normalization (`containsExactItalianSurface` in `src/italian/normalize.ts`); any other example is counted as rejected. | a generated sentence |

## Lookup
| Term | Definition | Not |
|---|---|---|
| candidate | One result of a lookup: a target record plus every piece of evidence that led to it, with its definitions, forms, articles, examples and provenance (`Candidate` in `src/core/types.ts`). A lookup returns every candidate the source supports; `sale` yields the salt noun, the plural of `sala` and the form of `salire`. | the chosen answer — ranking is a later, advisory step |
| provenance ref | The pointer every derived value carries, named as the schema names it: `release_id` the release, `line_no` the 1-based physical line of the source record, `json_pointer` inside that record, and `line_sha256` the digest of that line (`src/db/schema.sql`; `docs/RECORD_IDENTITY.md`). Code that carries a ref uses these four names. | the compact `{ r, i, p, h }` in `src/core/types.ts`, which is the pre-schema validation spike, not the contract |
| phrase match | How a query of several words that nothing spells reaches a multi-word headword: each word read as its lemmas (itself, whether or not a record heads it, and what its form-of records name), an auxiliary and a past participle read as the participle's verb, and every lemma sequence probed as an exact headword key. `vado via` finds *andare via*, and `faccio l'amore` finds *fare l'amore* though `l'amore` heads no record. Its page is the short page the [design manifest](../design-system-manifest.md) describes (`phraseMatches` and `phraseForms` in `src/lookup/phrase.ts`; rule `it-phrase/v1` in `src/italian/phrase.ts`; `match.via` `phrase` in the API). | a near phrase — that is an offer, not a result |
| near phrase | A query of several words corrected, as typed, so that it reads as a multi-word headword by the phrase-match reading: one word replaced by a headword spelling one edit from it, the last word completed from a headword, or a run of the words that reads as one. `vadoo via` offers "Did you mean vado via?", and searching `vado via` finds *andare via*. The offer is always what a reader types, never the headword; it carries the `headwords` it reaches (`PhraseOffer`, `nearPhrases` in `src/lookup/phrase.ts`; a `suggestions` entry of `kind` `phrase` in the API). The search field's suggestions add the same completion while a phrase is typed: `vado v` → `vado via` (`phraseCompletions`). | a result — the query still finds nothing; a guess — every offer is read back the way its search reads it and names only the headwords that search finds, so no offer leads to "No entry"; and the headword itself — `andare via` is where the offer leads, not what it says |
| verb form line | The line a word page builds to say which cell of a verb's table a searched form fills, when no record about the form names that verb: `sono andato`'s block `1 · Voce verbale · andare` has "prima persona singolare del passato prossimo indicativo di andare". Built by rule `it-verb-form-line/v2` from the cell `it-moods/v1` places it in (`verbFormLine` in `src/italian/verbFormLine.ts`), at page time, and carried as `lexema-deterministic` with the `forms[]` pointer it came from (`VerbFormLine` in `web/lib/dictionary/wordPage.ts`; #627). A searched feminine compound form (`sono andata`, the reflexive `mi sono accorta`) reaches the cell of its masculine by rule `it-essere-agreement/v1` (`src/italian/essereAgreement.ts`), and its line names the gender after the number: "prima persona singolare femminile del passato prossimo indicativo di andare"; a masculine line names none. The rule reads only a cell's first spelling, the text before the first `, `, so `mi sono arresa` and `mi sono arreso` both reach arrendersi's `mi sono arreso, arresosi` ([#676](https://github.com/povlabs/lexema/issues/676), [Huey's ruling](https://github.com/povlabs/lexema/issues/676#issuecomment-6013478337)). Since v2 a cell of the non-finite line is named as the table names it: `stato` gets "participio di essere" ([#695](https://github.com/povlabs/lexema/issues/695)). | a definition from the source — no record holds it, and the seed never stores it; a form-of gloss — that is a record's own text, read by `it-verb-form-gloss/v1`; generated text — no model writes it (ADR 0008) |
| grid form line | The line a word page builds to say which cell of a noun's or adjective's grid a searched form fills, when no record about the form says anything: `gravida`'s block `1 · Aggettivo, forma flessa · femminile, singolare` has "femminile singolare di gravido", in the names the grid heads its rows and columns with. Built by rule `it-grid-form-line/v1` (`gridFormLine` in `web/lib/dictionary/gridFormLine.ts`) at page time and carried as `lexema-deterministic` with the `forms[]` pointer the query hit (`GridFormLine`). The block it opens, `GridFormBlock` in `web/lib/dictionary/wordPage.ts`, shows the base word's *Definitions* and *Forms of <word>* under it ([Huey's rule 4 of 2026-10-06](https://github.com/povlabs/lexema/issues/695#issuecomment-6024404411), [#700](https://github.com/povlabs/lexema/issues/700)). | a form-of gloss — that is a record's own text; a verb form line — that names a verb's table cell |
| verb form block | One verb a searched form belongs to, as its word page shows it: headed `N · Voce verbale · <verb>`, then that verb's form-of lines, the form record's definitions its `form_of` edges put there and verb form lines, then *Forms of <verb>* opened at the searched cell. `salivate` has two, salire's and salivare's (`VerbFormBlock` in `web/lib/dictionary/wordPage.ts`; #636). | a reading — it can hold lines of several records and none, and the verb it names has no reading of its own; a declared lemma's page — that has no definition |
| base word | The word a searched form's block shows the *Definitions* and table of: the word its `form_of` edge names, of its own part of speech when it names one, followed through a record that is itself a form to the word that one names. `bellissima` → `bellissimo` → `bello`; `costruttrici` → `costruttrice` → `costruttore`. A form shows one block per base word ([Huey's rule 1 of 2026-10-06](https://github.com/povlabs/lexema/issues/695#issuecomment-6024404411); `formBasesOf` in `web/lib/dictionary/wordPage.ts`). | the lemma a single edge names — that may itself be a form; a word only a gloss names — `parti`'s lines about `parto` name it in text, and their edges name `neonato` and `Parti` |
| unclassified form | A surface form kept with its raw tags and a `reason` when its grammar cannot be mapped safely (`UnclassifiedForm`; `targetForms` in `src/italian/adapter.ts`). It is returned, not dropped, and no article is generated from it. | an error |

## API
| Term | Definition | Not |
|---|---|---|
| API key | The secret a client of the JSON API sends as `X-API-Key`. Stored only as its SHA-256, with its own label (`api_key` in `src/db/app/schema.ts`; `src/api/keys.ts`). Either an admin key or an owned key. | a visitor key — the per-visitor rate-limit identity the site derives from an address (`visitorKey` in `web/worker/shared/rateLimit.ts`) |
| admin key | An API key made with `pnpm run api-key` (`src/api/keyCli.ts`). It has no owner (`owner_account_id` is NULL), carries its own per-minute limit, and no developer account can list or revoke it. | an owned key |
| owned key | An API key a developer account made for itself (`src/api/ownedKeys.ts`). It carries no per-minute limit of its own: its rate is its account's, and the schema refuses one that has a limit. It may be limited to some endpoints and given an expiry (`src/api/keyAccess.ts`); an admin key has neither. Its owner is that account; only that account lists or revokes it, and a deleted account's owned keys stay stored, revoked. | an admin key |
| display prefix | A key's first 11 characters, `lx_` and 8 hex digits, stored beside its hash so the key can be named without its secret (`displayPrefix` in `src/api/keys.ts`). | the key — the rest is never stored |
| call | What API usage is counted in: every answered request is 1 call, and `lookup/batch` is 1 call per word it is sent (`CALL_BASIS` and `callCost` in `src/api/calls.ts`; Huey, #183). Summed per key per UTC day in `api_key_usage.calls`. | a request — a batch of 7 words is one request and 7 calls; nor the retired *unit*, the per-endpoint weight calls replaced (#201) |
| account meter | The count of one developer account's calls: a SQLite-backed Durable Object per account, named by its id, around the pure `AccountMeter` (`src/api/accountMeter.ts`, `web/worker/api/accountMeterObject.ts`). One call per API request admits the request's calls and adds them to the period and to the key's UTC day in its own storage, and a second call, made only when the answer then fails, gives them back (#289); at most once a minute it adds the days' calls to `api_key_usage`. | an in-memory counter, which hibernation would lose; the per-minute rate, which Rate Limiting bindings count except for a rate neither binding holds |
| plan | What a developer account pays for: Starter or Pro, bought through Stripe, whose allowance, rate and price are the one table `PLAN_TERMS` (`src/billing/plans.ts`; Huey, #183), or Enterprise, set by hand with its own (`pnpm run plan`). There is no free plan. | a plan state — the plan says what was bought, its state whether it serves now |
| plan state | Where an account stands with its plan: none, active (renewing at its period's end), past due, cancelling (serving until its end date) or ended (`PlanState` in `src/billing/plans.ts`). Read from the account's live Enterprise plan if it has one, else its newest subscription, else none (`accountPlan` in `src/billing/accountPlan.ts`). Active and cancelling before its end serve calls (`serving`), except an Enterprise period past its end (#222); past due does not, until the payment goes through (#571); an owned key whose account's plan does not serve answers 402. A past-due plan is still held (`holdsPlan`): choosing a plan goes to the billing portal, and Enterprise is not set over it. | a Stripe subscription status — eight statuses map onto these five states |
| allowance | A plan's calls in one billing period (`callsPerPeriod` of `PlanLimits` in `src/billing/plans.ts`): the table's for Starter and Pro, agreed for Enterprise. The plan's other limit is its rate, calls a minute per account. | a per-key limit — an admin key's `per_minute_limit` is its own, outside any plan |
| billing period | The span an allowance is counted over and resets after: the Stripe subscription item's current period, or the dates Huey sets for Enterprise, from its start up to, not including, its end (`Period` in `src/billing/plans.ts`). | a calendar month |
| subscription | One account's Stripe subscription, as the Stripe plugin (`@better-auth/stripe`) keeps it: a `subscription` row naming the account in `reference_id`, with its plan, Stripe status, period and pending cancel (`src/db/app/schema.ts`). The plugin writes it; Lexema only reads it (`stateOfSubscription`). | a plan state, which is read from it; nor an Enterprise plan, which is never a subscription |
| Enterprise plan | A plan Huey sets by hand for one account with `pnpm run plan`: its own allowance, rate and period, held in `enterprise_plan` and live until ended (`src/billing/planCli.ts`). The Stripe plugin never reads or writes it, and it cannot be set over a Starter or Pro plan the account still holds, serving or past due. | a subscription |
| plan notice | What a developer account was last emailed about one Stripe subscription: a plan state's kind and its plan, one `plan_notice` row per subscription (`src/billing/planNotice.ts`, #215). The webhook emails the difference between it and Stripe's current state, and moving the row is what claims those emails, so each is sent once. | the subscription row, which the Stripe plugin writes before Lexema's sync runs and so cannot say what changed |

## Developer site
| Term | Definition | Not |
|---|---|---|
| developer account | A person signed in to developers.lexema.fyi: better-auth's user, one row of `developer_account` (`src/accounts/accounts.ts`, `src/accounts/auth.ts`). It keeps the verified email it was made with, which a second provider links by, and its first provider's name; the account menu names it from its provider identities. Created on the first sign-in under a verified email no account has. Deleting it (`deleteAccount`, Lexema's, not better-auth's) revokes its keys, removes its sessions and identities, and replaces its email and name with values that say nothing about the person; the row stays, marked deleted, so its keys and usage keep an owner, and the next sign-in under that email makes a new account. | a Google or GitHub account — that is a provider identity |
| provider identity | One Google or GitHub account linked to one developer account: better-auth's account, by the provider's own id for the person, with the verified email it was linked with (`provider_identity` in `src/db/app/schema.ts`). It also keeps the name the provider gives the person, refreshed at each sign-in, for the account menu, and none of the provider's tokens. A second provider's identity with the same verified email links to the same account. | the account itself, or an unverified email, which is never stored |
| test developer | The one developer account a Preview's test sign-in reaches: a GitHub provider identity whose subject no real GitHub user id can equal, under `test-developer@example.com` (`src/accounts/testDeveloper.ts`). The sign-in page's *Sign in as test developer* button posts to `/sign-in/test-developer`, which signs it in to that Preview's own app database with no credential; only the `preview` stage on a Preview's developer host has the route or the button (`web/worker/developers/testSignIn.ts`, [#245](https://github.com/povlabs/lexema/issues/245)). | a real person's account; nor a stub provider, which only tests use |
| account email | One of the six emails Lexema sends a developer account from `noreply@lexema.fyi` through Cloudflare Email Service: plan started, plan changed, payment failed, cancellation confirmed, plan ended and account deleted (`AccountEmail` in `src/email/accountEmail.ts`, #215). Each is plain text and HTML laid out as Pencil board M1 (#367), with a button to settings when there is something to do there, and is sent at most once. | Stripe's own receipts, invoices, card-expiring and upcoming-renewal emails, which Stripe sends |
| session | A signed-in browser: better-auth's session, a random token stored with its account and expiry (`developer_session`), carried in a host-only `__Secure-` cookie on developers.lexema.fyi with better-auth's signature of it, made with `BETTER_AUTH_SECRET` (`src/accounts/auth.ts`). The token alone signs nobody in. It lasts 30 days and ends at sign-out or when its account is deleted. | an API key — a session never authenticates an API call |

## Hosting
| Term | Definition | Not |
|---|---|---|
| app database | The D1 bound as `APP_DB`, holding what the site itself writes: developer accounts, API keys, plans, usage and reader reports, in the Drizzle-defined app tables ([ADR 0017](../.decisions/0017-better-auth-and-drizzle-own-accounts.md)). One per stage: a local one, one per Preview (`lexema-preview-app-<name>`, where `<name>` is the Preview's name, made and migrated by the preview command), and production's ([ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | the dictionary database (`DB`), which holds the release, is shared by production and every Preview, and is never written by code |
| Preview | A Cloudflare Worker Preview of `lexema-web` for one branch, built by Workers Builds on each push to any branch but `main` and the merge queue's `gh-readonly-queue/` branches, which get none. Its name is its branch's name made into a DNS label (`web/builds/previewName.ts`, [docs/DEPLOY.md](../docs/DEPLOY.md#the-preview-name)). It answers the three sites at `<name>.preview.lexema.fyi`, `<name>.developers-preview.lexema.fyi` and `<name>.api-preview.lexema.fyi`, runs on the `preview` stage, reads the shared dictionary database, and its own dictionary slice when its branch has one, and writes only to its own app database. The sweep on each production build, after a green dictionary deploy, deletes it once its branch has no open pull request ([ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | a version preview URL (`wrangler versions upload --preview-alias`), which shares production's bindings; nor production |
| dictionary slice | A small D1 a Preview of a branch that adds change declarations gets, `lexema-preview-dict-<name>`, holding only the words those declarations touch: the shared dictionary's rows a lookup of them reads, with the declarations' changes applied. Only the preview command writes it, under a cap of 250,000 rows written. When the slice of every touched word is over the cap, it holds a sample: the words the declarations name in their `lookups` first, then more up to the cap; the touched words left out read the shared dictionary, and the build log names them (#741). The Worker binds it read-only as `DICTIONARY_SLICE` and reads it for those words alone, the shared dictionary for every other (`src/deploy/previewSlice.ts`, `src/lookup/slice.ts`, [docs/DEPLOY.md](../docs/DEPLOY.md#the-dictionary-slice), [ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | a copy of the dictionary, which it is not: other words are not in it; nor the app database |
| stage | Where the Worker is running, read from the `LEXEMA_STAGE` var: `local`, `preview` or `production`, parsed into a closed type so any other value refuses to boot. Preview-only behaviour, such as `X-Robots-Tag: noindex`, keys on it ([ADR 0018](../.decisions/0018-previews-on-workers-builds.md)). | a Wrangler environment (`env.production`), which is a build-time config block; nor a release's `importing`/`complete` status |
