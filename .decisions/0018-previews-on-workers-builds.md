# 0018 — Workers Builds deploys a Preview per branch and production after each green dictionary deploy, over one shared read-only dictionary D1

**What this decides:** Every branch gets its own public, noindexed preview of the three sites, built by Cloudflare from the connected repository; previews and production read one dictionary database and never write to it; each preview writes only to its own app database; and a merge to `main` deploys production once the dictionary deploy workflow has passed. GitHub holds two Cloudflare keys: one D1 Edit token that only that workflow reads, and one D1 read-only token that only the pull request plan check reads.

## Context

The `review-ui` gate captures only a pull request's announced preview, and this repository deploys none, so every `web/` pull request parks on a hand check by Huey ([#172](https://github.com/povlabs/lexema/issues/172), PR #170, PR #157). Epic #172 gives each pull request a preview of `lexema.fyi`, `developers.lexema.fyi` and `api.lexema.fyi`.

Huey ruled the design on #172 on 2026-09-30:

- [09:22](https://github.com/povlabs/lexema/issues/172#issuecomment-5908188492): previews run on Workers Builds, not a GitHub Action holding a Cloudflare token; a small Action with only `GITHUB_TOKEN` posts Fabrika's markers; previews are public with noindex; the preview email binding sends only to Huey.
- [09:49](https://github.com/povlabs/lexema/issues/172#issuecomment-5908694376): production and every Preview share one dictionary database, read-only by code; app data lives in a separate `APP_DB`; later releases apply as diffs.
- [10:09](https://github.com/povlabs/lexema/issues/172#issuecomment-5909073281), items 1, 3 and 4: a merge to `main` deploys production after the preview sweep; D1 Edit on the Workers Builds token is accepted; production bindings stay with [#19](https://github.com/povlabs/lexema/issues/19).
- [10:12](https://github.com/povlabs/lexema/issues/172#issuecomment-5909144970): no Cloudflare key in GitHub after all, so no close-cleanup Action; the sweep on each merge to `main` cleans up.
- [10:26](https://github.com/povlabs/lexema/issues/172#issuecomment-5909362893): the sweep reads open pull requests with a read-only GitHub token kept as a Workers Builds build secret.

The facts under these rulings were settled in grilling session [#238](https://github.com/povlabs/lexema/issues/238), mirrored on #172 ([R1](https://github.com/povlabs/lexema/issues/172#issuecomment-5908750659), [R2](https://github.com/povlabs/lexema/issues/172#issuecomment-5909132772), [R3](https://github.com/povlabs/lexema/issues/172#issuecomment-5909199824)), from these Cloudflare pages, read 2026-09-30:

- [Previews](https://developers.cloudflare.com/workers/previews/): one isolated Preview per name under one Worker; custom-domain Previews are not noindexed by Cloudflare; past 500 Previews per Worker the least recently deployed is evicted.
- [Previews, resources and isolation](https://developers.cloudflare.com/workers/previews/resources/): D1 is not provisioned per Preview. "Two Previews sharing the same `database_id` share rows"; to isolate one, bind a different D1, apply migrations to it, then run `wrangler preview` (#238 R1.1).
- [Previews, custom domains](https://developers.cloudflare.com/workers/previews/custom-domains/): a route with `previews_enabled: true, enabled: false` serves Previews only, at `<preview-name>.<domain>`.
- [Builds configuration, API token](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/#api-token): the Builds token has no D1 permission by default; it is edited in Cloudflare (#238 R1.2).
- [Builds configuration, environment variables](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/): a build sees only `CI`, `WORKERS_CI`, `WORKERS_CI_BUILD_UUID`, `WORKERS_CI_COMMIT_SHA` and `WORKERS_CI_BRANCH`, and no pull request state (#238 R3.2).
- [Build branches](https://developers.cloudflare.com/workers/ci-cd/builds/build-branches/): the production branch runs the build and deploy commands on every push; a custom preview command must still run `wrangler preview` (#238 R2.2, R3.1).
- [Previews, examples](https://developers.cloudflare.com/workers/previews/examples/) and [GitHub integration](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/github-integration/): Workers Builds comments the Preview URL on the pull request.
- [Email send bindings](https://developers.cloudflare.com/email-service/configuration/send-bindings/): a `send_email` binding with `destination_address` can send to that address only.

## Decision

**Workers Builds, connected to this repository, deploys a Worker Preview of `lexema-web` for every branch and deploys production after each merge to `main` once the dictionary deploy workflow has passed; every Preview and production read one shared dictionary D1 that the Worker never writes, and each Preview writes only to its own app D1.**

- **Previews on Workers Builds.** The repository is connected to Workers Builds with `production` as its production branch and preview builds on. Each branch gets one Worker Preview, named from the branch. Fork pull requests get none, since Workers Builds builds only this repository's branches.
- **Fabrika's markers from `GITHUB_TOKEN` alone.** A GitHub Action with only the built-in `GITHUB_TOKEN` reads Cloudflare's preview comment or check run and keeps one pull request comment with `<!-- preview-deploy:web -->`, `<!-- preview-deploy:developers -->` and `<!-- preview-deploy:api -->` blocks, each naming that site's deployment URL and `@ <head sha>`.
- **One Cloudflare key in GitHub that writes, for the dictionary deploy only.** Exactly one Cloudflare API token, scoped to D1 Edit only, is kept as a secret of a GitHub environment restricted to `main`, so a run on any other branch never receives it. Only the dictionary deploy workflow uses it (#443 R1.1, R2.1; #452 R1.3). Huey creates the token and the secret; no agent does.
- **One read-only Cloudflare key, for the pull request plan check only.** A second Cloudflare API token, D1 read-only (`D1 Read`, or the Content Read-Only role on D1 where Cloudflare offers roles), is kept as a secret of its own GitHub environment, `dictionary-plan`, which holds no other token (#498, amended by #527: `povlabs/lexema-data` is public and needs none). Only the pull request plan check uses it: a `pull_request` job, never `pull_request_target`, that runs only for this repository's own branches and only the plan-only entry, so it writes nothing (#494). It gives each change declaration its expected counts from the pull request's own code, and the deploy still holds every declaration to them at merge. No other workflow holds or reads a Cloudflare token. Huey creates the token, the environment and the secret; no agent does.
- **CI writes the shared dictionary.** After a merge to `main`, the dictionary deploy workflow, a GitHub Action, applies the dictionary changes the merge declares to the shared dictionary D1 through Wrangler, never through the Worker (#443 R1.1, R2.1). It records a D1 Time Travel restore point before it writes. When a check fails, it stops red and names the restore point; it never restores by itself (#443 R1.3). No agent holds the Cloudflare token, runs this workflow, or writes the shared dictionary.
- **`povlabs/lexema-data`: read without a token, written with one.** The dictionary deploy workflow and the pull request plan check read the archive and dump from the public `povlabs/lexema-data` with no token, and check each file's checksum before use (#527; formerly a read-only token, #452 R1.4, #498). A fine-grained token, scoped to write `povlabs/lexema-data` only, is used only by the monthly release job (#443 R3.1, #446 amendment). Huey creates that token and its secret; no agent does.
- **The sweep.** Each production build first deletes the Previews, app D1s and dictionary slices of branches with no open pull request, then deploys. A slice with no app D1 still names its branch's Preview, and the Preview goes before its D1s. A merged pull request is cleaned up at the production build that follows its merge; one closed without merging, at the next production build. The sweep reads open pull requests from GitHub's REST API (#238 R3.2). The repository is public, so no token is needed; `GITHUB_PR_READ_TOKEN`, an optional Workers Builds build secret, is sent when set (#527). When the list cannot be read, the sweep deletes nothing and the deploy still runs.
- **D1 Edit on the Builds token.** Huey adds D1 Edit to the Workers Builds token in Cloudflare. It reaches every database on the account, which is accepted because only reviewed build commands use it.
- **Three preview-only hosts.** `preview.lexema.fyi`, `developers-preview.lexema.fyi` and `api-preview.lexema.fyi` are custom domains that serve Previews only. The Preview for branch slug `<name>` answers at `<name>.preview.lexema.fyi`, `<name>.developers-preview.lexema.fyi` and `<name>.api-preview.lexema.fyi`, told apart by host like production. Previews are public, and every response on the `preview` stage carries `X-Robots-Tag: noindex`.
- **The stage is explicit.** `LEXEMA_STAGE` names where the Worker runs: `local`, `preview` or `production`. It is parsed into a closed type, and any other value refuses to boot. Preview-only behaviour keys on it.
- **One shared dictionary D1.** Production and every Preview bind `DB` to one remote dictionary D1. The Worker's dictionary binding stays read-only: code only reads through it, and a test fails if any code path writes through the dictionary binding. A Preview may also bind a dictionary slice beside it, below; `DB` stays on the shared dictionary either way. A release is uploaded into it once, seeded and verified as [ADR 0012](0012-archive-is-the-release-seed.md) says. Later releases apply as diffs, not full re-imports; how is [#132](https://github.com/povlabs/lexema/issues/132)'s and [#18](https://github.com/povlabs/lexema/issues/18)'s, and not decided here. Local development keeps its own local copy as the default.
- **The one-time upload is a laptop run.** Huey uploads a release from his machine, where the archive lives, with `seed:dev`'s remote target. It is not a workflow; the dictionary deploy workflow applies only the changes a merge declares.
- **`APP_DB` is the app database.** Accounts, keys, plans, usage and reader reports live on their own binding, `APP_DB`, locally, on Previews and in production. `DB` stays the dictionary.
- **One app D1 per branch on Previews.** The Workers Builds preview command creates `lexema-preview-app-<branch>` if absent, writes its id into the built config's Preview binding, applies the app migrations to it, then runs `wrangler preview`. Production's `APP_DB` is #19's.
- **One dictionary slice per dictionary-changing branch (#447).** When a branch adds change declarations past `main`, the preview command plans them against the shared dictionary, through read-only statements only, and gives the branch's Preview a slice D1, `lexema-preview-dict-<branch>`. It holds only the words the declarations touch: the shared rows a lookup of those words reads, with the pull request's changes applied. The preview build is the only writer of a slice. It counts the rows a write would write first, index entries included, and writes nothing over 250,000; a build whose declarations and schema are unchanged reuses the slice and writes nothing. The slice is bound read-only as `DICTIONARY_SLICE`, beside `DB`. A lookup of a word the slice serves reads the slice, so a word the pull request hides reads as not found there; every other word reads the shared dictionary. A branch with no declaration, or whose declarations have no bounded word set or cannot be planned in the build, gets no slice and today's Preview.
- **`production` follows the dictionary.** The Workers Builds production branch is `production`. Only the dictionary deploy workflow advances it, with `GITHUB_TOKEN`, to the run's commit after a green run; a red run leaves it where it is (#452 R1.1). So the site never deploys ahead of the dictionary it reads. The Workers Builds production command runs the sweep, then `wrangler deploy` with the production build. Binding the shared dictionary and a production `APP_DB` into `env.production` stays with #19, under ADR 0013's binding constraint.
- **Preview email goes only to Huey.** The Preview `send_email` binding carries `destination_address` set to Huey's verified address, so it can send nowhere else.
- **Previews keep apart from production.** A Preview never binds a production `APP_DB` or a production secret, and uses its own rate-limit namespace ids.

**Binding constraints.**

- Exactly two Cloudflare credentials are given to GitHub. One API token scoped to D1 Edit only, kept as a secret of a GitHub environment restricted to `main`, is used only by the dictionary deploy workflow (#443 R1.1, R1.3, R2.1, R3.1; #446 amendment; #452). One API token scoped to D1 read-only, kept as a secret of its own environment `dictionary-plan` that holds no D1 Edit token and no token that writes `povlabs/lexema-data`, is used only by the pull request plan check, which runs only the plan-only entry and never on a fork (#494). No other GitHub workflow holds, reads or is given a Cloudflare credential.
- No agent holds the Cloudflare token, runs the dictionary deploy workflow, or writes the shared dictionary.
- Only the dictionary deploy workflow advances the Workers Builds production branch `production`, and only after a green run.
- The dictionary deploy workflow and the pull request plan check read the public `povlabs/lexema-data` with no token, and check every file's checksum before use. The only token for `povlabs/lexema-data` is the one that writes it, used only by the monthly release job (amended by #527).
- No code path writes through the dictionary binding, and nothing writes the shared dictionary but the dictionary deploy workflow. A Preview's dictionary slice is written only by the preview build, which reads the shared dictionary through single SELECTs and refuses to create, write or delete a D1 whose name or id is the shared dictionary's; the Worker binds the slice read-only (amended by #447).
- Each Preview binds its own app D1, never another branch's and never production's, and at most its own branch's dictionary slice.
- Every response on the `preview` stage carries `X-Robots-Tag: noindex`.
- The Preview `send_email` binding always carries `destination_address`.
- Every Workers Builds setting and build secret is written down in `docs/DEPLOY.md`, per ADR 0013's last binding constraint.

## Consequences

- Every `web/` pull request can be captured by `review-ui render` at its head, with `--app developers` or `--app api` for the other two hosts, without a hand check.
- `production` trails `main` by one dictionary deploy run. A reviewed merge goes live with no human step once that run is green, so the merge gate of [ADR 0006](0006-codex-review-is-the-merge-gate.md) is now also the deploy gate, and a broken merge stays live until something replaces it. A red run holds the site at its last green commit.
- Previews are public and serve the dictionary before production does. They carry the same *Source* links and `/attribution` page as production, so the licence terms ADR 0013 checked apply to them unchanged. ADR 0013's rule that production gains a D1 only once the release records its source dump is left as it stands, with #19.
- The dictionary D1 is shared, so a bad write would reach production and every Preview at once. The read-only binding and its test stop one from the Worker. CI's writes are guarded by the deploy workflow's restore point and checks, and a bad one is undone by a person running the restore, never by the workflow.
- A GitHub secret can now edit every D1 on the account, as the Builds token already can. The environment restricted to `main` and the reviewed workflow are what keep it to the dictionary deploy.
- A second GitHub secret can read the D1s it is scoped to, and this repository's pull request code runs with it: a branch pushed here can read the dictionary, or any D1 the token reaches, though it can change none. That is the tradeoff Huey accepted on #494, for one pull request per change with no hand-started run. A fork's pull request never receives it.
- A hide or a feed release takes one pull request as well (#498): the plan check reads the public `povlabs/lexema-data` with no token (#527), so no data token reaches pull request code. The plan check's job may run as long as the deploy's own plan job, since it downloads an archive and a dump.
- A closed, unmerged pull request's Preview, app D1 and dictionary slice live until the next production build, which runs only when a green dictionary deploy run advances `production`.
- A pull request that changes dictionary data shows its change on its own Preview, so `review-ui` can judge it before merge (#447). Each slice write costs at most 250,000 of the 50 million rows written a month that Workers Paid includes, and a push that changes no declaration writes none. The preview build of such a branch also plans its declarations, which reads the shared dictionary and may download an archive and a dump, inside Workers Builds' build time. A slice holds only the touched words, so a lookup there lists the multi-word expressions and inflections of other words only as far as the slice holds them.
- The Builds token can edit every D1 on the account, including the dictionary. Build commands are reviewed like any other code.
- The build pipeline now lives in Cloudflare's dashboard as well as the repository, so it can drift; that is why its settings go into `docs/DEPLOY.md`.
