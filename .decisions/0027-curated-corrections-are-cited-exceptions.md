# 0027 — A source fact may be corrected by a cited, ruled layer beside the record, never by editing the record

**What this decides:** When the source states a fact wrongly, Lexema may set it right by hand, one cited fact at a time and only on Huey's ruling. The imported record is never changed; the correction sits beside it.

## Context

AGENTS.md says source-derived lexical data is read-only, with one exception: the fixed, rule-based rewrite of [ADR 0019](0019-source-text-may-be-normalized.md). PR [#448](https://github.com/povlabs/lexema/pull/448) ([#420](https://github.com/povlabs/lexema/issues/420)) added a second kind of change: hand-made *curated corrections* that set a record's gender or number right, each citing a Wiktionary revision. Huey ruled on #420 to "fix it now", in our curated master, which may carry hand-added facts that cite their evidence ([#18](https://github.com/povlabs/lexema/issues/18)). No record allowed this layer, so a future agent following AGENTS.md could remove the corrections or refuse to add more. More corrections are coming through the same layer ([#449](https://github.com/povlabs/lexema/issues/449), [#450](https://github.com/povlabs/lexema/issues/450), [#470](https://github.com/povlabs/lexema/issues/470)).

Huey ruled on 2026-10-03 to record the layer as an ADR and name it in AGENTS.md as the second exception ([ruling on #472](https://github.com/povlabs/lexema/issues/472#issuecomment-5969543528): "yes write it, 448 merged"). This record transcribes that ruling and the rulings already made about the layer. It describes the layer as it exists on `main`; it adds no new dimension.

This record amends [ADR 0012](0012-archive-is-the-release-seed.md) in part. Its binding constraint "Any other seed-time input is a new decision" is met here: the seed also reads the committed correction list and writes it as its own layer. ADR 0012's rule that the archive line of every record is stored unaltered stands, and so does its rejection of correcting a record in place, because a correction never edits the record.

## Decision

**Lexema may correct a fact the source states wrongly through a curated correction: a cited, separately stored layer beside the record, added only on a ruling, while the imported record stays byte for byte.**

- **A separate layer, never an edit.** A correction names one record by release, archive line and line digest, and sets one or more facts. The record's line in `source_record_json` stays byte for byte, and so do its `grammar_claim` rows. Today the facts are gender and number (`CorrectableValues` in `src/italian/curatedCorrections.ts`). Gender and number corrections are stored as `corrected_claim` rows, written at seed by `src/import/correctedLayer.ts` and into an already seeded master by `src/import/correctRecords.ts`. A lookup reads them in place of the source's claim in that dimension (`correctRecordClaims` in `src/lookup/types.ts`). [ADR 0030](0030-corrections-may-fix-edges-and-cells.md) adds two more kinds, a `form_of` edge and a conjugation cell. This record's binding constraints hold for them, but their storage is left to the issue that builds them.
- **Every correction is cited, and added only on a ruling.** Each entry carries at least one Wiktionary revision id and what that revision shows (`Evidence`, `evidenceUrl` in `src/italian/curatedCorrections.ts`). The committed list says "Add an entry only with its evidence, and only on a ruling." Rulings so far: [#420](https://github.com/povlabs/lexema/issues/420) ("fix it now") and [#450](https://github.com/povlabs/lexema/issues/450).
- **Plain data on the page.** The page shows the corrected fact as ordinary data and says nothing about the correction ([ADR 0016](0016-page-shows-no-origin-marks.md)).
- **A later release does not inherit a correction.** When a feed change replaces a corrected record, the update reports the correction (`retiredCorrections` in `src/update/apply.ts`) and does not carry it onto the new record. The correction stays on the retired record. The newer source may state the fact differently, so whether to correct the new record is a new ruling. This sits beside [ADR 0025](0025-newer-source-definitions-are-authoritative.md), whose binding constraints already keep hand-added rows when later source updates land.
- **Wording Lexema writes needs Huey's approval.** Per the [#450 ruling](https://github.com/povlabs/lexema/issues/450#issuecomment-5968691876), a builder may write a corrected definition paraphrased from cited dictionaries, and Huey approves the exact wording on the PR. How such text is labelled is [ADR 0008](0008-generated-explanations-are-labelled-and-reportable.md)'s question, and how it meets ADR 0012's "No text authored by Lexema is written by the seed" is open too; both are #450's work, not this record's.
- **How it differs from ADR 0019.** [ADR 0019](0019-source-text-may-be-normalized.md)'s source text normalization is a fixed rule over many rows that never changes meaning. A curated correction is a single cited fact about one record that changes meaning on purpose, because the source is wrong. Neither rewrites `source_record_json`.

**Binding constraints.**

- A correction never edits the record: `source_record_json` and the record's imported rows stay as imported.
- No correction without at least one cited source revision, and none without a ruling.
- No mark of a correction on the page.
- A correction is never carried onto a record that replaces the corrected one; the update reports it.
- No definition wording Lexema writes lands without Huey's approval of the exact wording on its PR.
- No AI-generated fact enters this layer. Wording an agent drafts enters only after Huey approves it on the PR (#450).

## Consequences

- The corrections from #420 are allowed law, not a breach of the read-only rule, and new ones have a known route: an issue, a ruling, cited evidence, an entry in the committed list.
- Each correction costs a ruling and a citation. That is on purpose, so the list stays short and every entry is provable.
- A feed update can leave a word uncorrected again when it replaces the record. The update's report names each such correction, so a person can decide whether to rule again.
- Adding a new dimension (such as definitions in #450) extends this layer under these rules; it is that issue's work, not a new exception.

## Amendments

- **A ruled rule may make corrections, each citing the pinned revision that confirms it (2026-10-03).** About 290 records gloss themselves "plurale di …" and are tagged singular, and many also carry the wrong gender ([#483](https://github.com/povlabs/lexema/issues/483)). Huey ruled to fix them with one rule, not by hand ([ruling](https://github.com/povlabs/lexema/issues/483#issuecomment-5970891514): "ok"). This narrows "by hand, one cited fact at a time" for that rule only.
  - **What may confirm a correction.** A real plural's number, and its gender where wrong, change only where the record's own en.wiktionary page confirms them. A singular noun whose gloss wrongly says "plurale di" (`mima`, "femminile plurale di mimo") may also be confirmed by the it.wiktionary table of forms (`{{Tabs|…}}`) on its lemma's page, pinned by revision. Huey accepted that on 2026-10-03 for these nouns only ([ruling](https://github.com/povlabs/lexema/issues/483#issuecomment-5971809939): "yes a"); it is the kind of evidence #420 used for `ammaliatrice`. Six of the 15 corrected nouns cite only that table: `mima`, `tuttologa`, `sicaria`, `smacchiatrice`, `giostraia` and `bucaniera`.
  - **How the rule runs.** Rule `it-plural-gloss-number` (`src/italian/pluralGlossNumber.ts`; v1 for #483, v2 for #515, v3 for #516) is named and versioned like an [ADR 0019](0019-source-text-may-be-normalized.md) rule, but it changes meaning on purpose, so it is a curated correction and not a normalization. It reads only the record's archive line and Wiktionary revisions pinned by revision id (`src/italian/pluralGlossEvidence.ts`, written by `pnpm run measure:plural-gloss`). So the same release and the same revisions always give the same corrections, and no record is judged by hand.
  - **What each correction is.** An entry of the committed list like a hand entry: keyed to its archive line and digest, citing the revision that confirms it, stored as `corrected_claim` rows beside a record whose line stays byte for byte, and shown on the page with no mark ([ADR 0016](0016-page-shows-no-origin-marks.md)). A record a hand entry names is never also corrected by the rule. A record no pinned revision confirms stays as the source states it, listed in the report with the reason.
  - **How it changes.** Changing what the rule confirms is a new version and a new ruling. Re-pinning its revisions is a pull request whose changed corrections show in the diff. Every binding constraint above still holds.
  - **Version 2 (2026-10-03).** Rule v1 left real plurals unchanged in two shapes ([#515](https://github.com/povlabs/lexema/issues/515)). Huey ruled that both count as en.wiktionary confirmation ([ruling](https://github.com/povlabs/lexema/issues/515#issuecomment-5971932437): "yes to all 3"), so `it-plural-gloss-number/v2` accepts both:
    - **Case 1, accepted: the gloss names the feminine singular.** `platoniche` says "plurale di platonica", and its en.wiktionary page says `{{adj form of|it|platonico||f|p}}`. A record is corrected only when the pinned en.wiktionary revision of the gloss's lemma names that lemma the feminine singular of the template's lemma (`{{adj form of|it|platonico||f|s}}` on `platonica`). The correction cites the word's own revision and the lemma's revision.
    - **Case 2, accepted: the plural is filed under a neighbouring part of speech.** `virtuosi` is a noun record, and en.wiktionary has it only as an adjective. A record is corrected only when its own pinned en.wiktionary revision states it a plural of exactly the gloss's lemma, in a section of the other part of speech (an adjective's or participle's for a noun, a noun's for an adjective). Its gender changes only where that same revision states one gender.
    - v2 corrects every record v1 corrects, identically. A record neither case confirms keeps its v1 reason.
  - **Version 3: singular adjectives too (2026-10-03, [#516](https://github.com/hueypov/lexema/issues/516)).** Huey ruled that a singular adjective whose gloss wrongly says "plurale di" (`rosa`, "femminile plurale di roso") gets the same correction as the nouns ([ruling](https://github.com/hueypov/lexema/issues/516#issuecomment-5971933388): "yes to all 3"). Only the adjective's own en.wiktionary page, pinned by revision, may confirm it: an `Adjective` or `Participle` section that names it a singular of the gloss's lemma, and none that names it a plural. No lemma page and no it.wiktionary table counts for an adjective. Rule `it-plural-gloss-number/v3` corrects the 37 such adjectives of `it-0c432803` and corrects every record v2 corrects, identically ([report](../reports/2026-10-03-plural-gloss-singular-adjectives.md)).
- **A correction may set a noun's or adjective's listed form (2026-10-17).** `eguale`'s it.wiktionary page ([revision 3907185](https://it.wiktionary.org/w/index.php?title=eguale&oldid=3907185), in dump `itwiktionary-20260701`) writes `{{Pn}} ''m'' e ''f sing'' {{Linkp|equivalenti}}`, so the source lists `equivalenti`, another word, as its only form, tagged plural. `eguali` therefore found nothing, and eguale's page showed a dash for its plural ([#830](https://github.com/povlabs/lexema/issues/830)). en.wiktionary's `eguali` ([revision 68995164](https://en.wiktionary.org/w/index.php?title=eguali&oldid=68995164)) says `{{plural of|it|eguale}}`. Asked whether to set eguale's plural right with a cited correction, Huey answered ([ruling](https://github.com/povlabs/lexema/issues/830#issuecomment-6233334459)): "yes to all three as proposed". [ADR 0030](0030-corrections-may-fix-edges-and-cells.md) allows only a verb's conjugation cell, so this adds the kind.
  - **What may be corrected.** One entry of a noun's or adjective's `forms[]`, by its place, quoting the text the line holds there, on a ruling naming it. Its spelling is the one the cited pages give. The first is `eguale`'s `forms[0]`, `equivalenti`, which reads `eguali`.
  - **How it is stored and read.** As a conjugation cell is: the same `CellCorrection` entry in `src/italian/curatedCorrections.ts`, here also naming its ruling as data, and one `corrected_form` row beside the record. A lookup reads the corrected spelling in place of the source's, and a search finds it (`eguali` finds eguale). `source_record_json` and the record's `lookup_form` and `grammar_claim` rows stay as imported, and the form keeps the number its line states.
  - **Where it sits on the page.** The gender grid does not guess the gender of a form that states a number and no gender on a record of both genders (`fine` lists `fini`). A corrected form is the one exception: the cited page settles it, so it fills that number in every gender its record states. `eguali` fills both plural cells of `eguale`, which is `m e f`. The page shows it as plain data, with no mark ([ADR 0016](0016-page-shows-no-origin-marks.md)).
  - Every binding constraint above holds: evidence, a ruling, no inheritance by a record a later release puts in its place.
- **A correction may add forms to an adjective's table and remove forms from it (2026-10-17).** `quello`'s adjective record (archive line 33211 of `it-0c432803`) lists `quelli`, `quella` and `quelle`, the table its it.wiktionary page gives it ([revision 4042892](https://it.wiktionary.org/w/index.php?title=quello&oldid=4042892), `{{Tabs|quello|quelli|quella|quelle}}`, the pronoun's table too). So the word page showed `quelli`, the pronoun's plural, as the adjective's, and none of `quel`, `quell'`, `quei` and `quegli`, the forms the adjective takes before a noun. `bello`'s adjective record lists none of `bel`, `bell'`, `bei` and `begli` either. en.wiktionary lists them all ([quello, revision 90494248](https://en.wiktionary.org/w/index.php?title=quello&oldid=90494248); [bello, revision 91582021](https://en.wiktionary.org/w/index.php?title=bello&oldid=91582021)). The kind of 2026-10-17 above sets one listed form's spelling, and none can add a form or remove one ([#836](https://github.com/povlabs/lexema/issues/836)). Huey ruled yes ([ruling](https://github.com/povlabs/lexema/issues/836#issuecomment-6237109728)): add the missing forms as cited corrections citing en.wiktionary, drop `quelli` from quello's adjective table while its pronoun keeps it, only add to bello's (`sono belli` is right), through a new kind for an adjective's forms amending this record.
  - **What may be corrected.** An adjective's table of forms, on a ruling naming the forms. A correction adds a form by its spelling, gender and number, as a cited page gives them, and removes an entry of the record's `forms[]` by its place, quoting the text the line holds there. A form a cited page gives to two genders is added once for each: `quell'` and `bell'` stand before a vowel of either gender, so each is masculine and feminine singular. The first two entries are quello's, five forms added and `quelli` removed, and bello's, five forms added.
  - **How it is stored and read.** A new kind of correction names the record by release, archive line and line digest, and lists its added and removed forms; it cites the pages and the ruling (`AdjectiveFormsCorrection` in `src/italian/curatedCorrections.ts`). The seed and `correct:records` write one `corrected_adjective_form` row per form beside the record, only where the line is an adjective's, holds each removed form's text at its place and lists no added form already; they refuse an entry that misquotes its own line. A lookup reads the rows beside the record's own forms (`Reading.formCorrection`), and the gender grid places each added form in its cell and leaves each removed one out. `source_record_json` and the record's `lookup_form` and `grammar_claim` rows stay byte for byte, so a search still finds the record by a removed form's spelling. The page shows the table as plain data, with no mark ([ADR 0016](0016-page-shows-no-origin-marks.md)).
  - **On a newer release.** As for every kind above: a record whose line a later release changed is reported, not corrected, and a record that replaces the corrected one does not inherit it ([ADR 0025](0025-newer-source-definitions-are-authoritative.md)).
  - **Articles, decided beside it.** The same ruling has the grid draw no article line for a determiner adjective, which stands where an article would (`quel libro`, never `il quel libro`). That is no correction: it is a rule over a closed list of headwords (`ARTICLELESS_DETERMINERS` in `src/italian/determiners.ts`), never the source's `Aggettivo dimostrativo` label, since `siffatto` carries that label and takes an article.
